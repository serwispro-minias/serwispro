# Contributing to SerwisPRO

Thank you for considering contributing! A few basic guidelines:

- Code style: follow project's existing conventions. Use black/flake8 where configured.
- Tests: add unit tests for any new logic. Keep business logic testable (services, repositories).
- Commits: write clear messages; prefer small, focused commits.
- Pull requests: describe the change and why; reference relevant issues.
- Code review: address comments promptly and keep changes small.

Process:
1. Fork the repository and create a feature branch.
2. Run tests locally before pushing.
3. Open a pull request against `main` and assign reviewers.

If in doubt, open an issue to discuss the proposed change before implementing.
